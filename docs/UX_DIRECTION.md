# UX Direction

## Experience
VoiceCity should feel like a focused desktop audio workspace, not a generic AI dashboard.

## Main navigation
1. Voice Library
2. Create Speech
3. Generation History
4. Settings

## Primary workflow
1. Add a voice: local file picker with supported formats and reference requirements.
2. Inspect recording: preview, duration, sample rate, channels, clipping, and validation.
3. Prepare profile: model-specific progress and requirements; name the profile.
4. Create speech: text input, language selector, voice selector, generation action.
5. Review output: player, duration, status, retry, and previous attempts.
6. Export: format and destination controls with visible local storage location.

## UX principles
- Calm, precise, tool-oriented interface.
- Light theme as initial default.
- Clear distinction between a voice profile and generated audio.
- No fake progress, fabricated output, or misleading model-ready status.
- Explain technical errors in plain language with a useful next action.
- Show whether processing is local or remote at point of use.
- Never promise perfect accent, emotion, or language reproduction.
- Keyboard navigation, readable contrast, visible focus, responsive layout.

## Initial screens
- Empty Voice Library
- Import Voice dialog
- Audio Inspection
- Voice Profile Detail
- Create Speech workspace
- Generation in progress
- Generation result and comparison
- History
- Model and privacy settings
- Missing model and unsupported language states

## Visual direction
Restrained typography, generous spacing, strong hierarchy, neutral surfaces, and a small functional accent palette. Avoid dark gradient-heavy AI styling, decorative charts, and unnecessary dashboard cards.
